# w10lf -- the leak-free 10-epoch run: PRE-REGISTRATION

Written 2026-09-10 ~23:15, **before phase L has produced any number** (arm 2's decay is at step
~13,700 of 21,870; phase L runs at the start of its eval, ~07:50 on 09-11).

## Why it exists

Andrew 2026-09-10, after the query-row clock leak was confirmed and fixed:
*"I think we should do a leak-free run anyway. Nothing that cheats should make it into the final
version that will be shipped."*

So this run is not conditional on phase L. `w10clk` (a leak-free DECAY from ws10's leaked WS)
remains a measurement; this run is the BASE of the shipped model: no weight of it ever trained on
a clock column that carried the current review's excess.

## What it is

`scratchpad/w10lf/run_w10lf.cmd`, generated by `mk_w10lf.py [T]`:

| phase | what | control |
|---|---|---|
| A | ws10's WS from scratch: 109,350 steps, ws10's toml (save folder/prefix only) | ws10 |
| B | arm 1's 2-epoch decay (21,870 steps) from this run's own WS-final | arm 1 (`w10plain`) |
| C | arm 1's rectified VAL-half eval, users 5001-7500, 6701 excluded | arm 1 |

`RWKV_CLOCK_AT_PREV_ANSWER=T` in all three phases. **T comes from phase L by the rule already
pre-registered for w10clk** (`clk_decide.py`: T=10800 if the 3 h window costs >= +0.0005 imm more
than the 30 min one, else T=1800).

The fix as of this run (`rwkv/clock_fix.py`): query and probe rows move to the previous answer on
an in-session gap; the continuous clock columns shift; **a shift past UTC midnight also takes the
previous day's dow / doy / is_weekend / review-time cycles** (added today -- those rows fail at
0.29 against 0.14 on other moved rows, so they did leak); the ahead label time loses the target's
in-session gap.

**Known residual, measured, not assumed** (`scratchpad/leak/residual_channels.py`, users
5001-5040, T=1800): the Anki-day columns change on 0.0036% of query rows and the creation-batch
counts on 0.021%, at P(fail) 0.10 (n=70) and 0.16 (n=399) against 0.14 -- 2.7e-7 and 3.3e-7 nats
per query row, the plug-in estimator's own bias floor. A stored row cannot recompute them; closing
them needs an LMDB rebuild. Stated so the "leak-free" label carries its exact scope.

One env difference from ws10 in phase A: `OMP_NUM_THREADS=7` (ws10 lost it by accident; arm 1 and
every later branch have it). CPU thread counts in the fetch workers only.

## Predictions

Deltas are `w10lf - w10plain`, positive = w10lf WORSE, n = 2,499, rectified.

* **P1 the leak's value after full adaptation.** imm **+0.0005 .. +0.0030**; ahead **+0.0000 ..
  +0.0006**. imm carries most of it because the query row is the imm prediction; ahead sees it
  only through the PAVA probes and the label time.
* **P2 against phase L** (users 5001-5300, imm): w10lf's cost is **0.2 .. 0.7** of lkc30m's
  (training from step 0 recovers part of what an unchanged model loses). Above 1.0 = a defect.
* **P3 against w10clk, if it ran:** w10lf imm <= w10clk imm + 0.0003. A full leak-free WS losing to
  a decay-only fix by more than that is a defect to find, not a result.
* **P4 stop criterion:** ahead NOT met (arm 1 already misses 0.2950 by 0.0026). imm <= 0.2640:
  **about 50%** (arm 1 has 0.0019 of room, P1's midpoint spends most of it).
* **P5 engagement:** the ON banner and the chunk-count line in the WS log and the decay log
  (runner guards 56-59); `day crossings` > 0 on the WS log's last clock-fix line.
* **P6 speed:** WS within 5% of ws10's 0.80 steps/s. The fix is CPU work in fetch workers whose
  wait was already 3-7 ms and hidden.
* **P7 size:** 0/2,499 mismatches against arm 1 (same dbs, same label filter).

## What follows from the number

* It is the reference for the shipped model. The deploy QAT decay (arm 2 on THIS WS, with KD if
  the QAT-KD arm wins, at the decay length the decay-length pair picks) follows it; the catalogs
  must be refit on this WS-final first (`run_fit_catalogs.cmd`'s procedure).
* The stop-criterion status is re-stated on the leak-free basis, whichever way P4 falls.
* The claims suspended on 2026-09-10 ("imm stop criterion met", "beats d=128 on imm") are
  re-decided here, not by phase L alone.

## Placement (decided 2026-09-10, revisited once phase L reports)

Default: the END of the queue, behind the decay-length pair (`wait_decaylen_then_lf.cmd`), so the
experiments before it (cmixgraft, QAT-KD, budget curve, decay length) can shape the final recipe.
**If phase L says MATERIAL** (imm >= +0.0010 at 30 min), the plan is to move this run behind
cmixgraft and re-base QAT-KD, the budget curve and the decay-length pair on this WS instead of
ws10 -- at a leak that large their imm conclusions on a leaked base are not safe (KD from a leaked
teacher can pass the leak on). That move is done by hand.
